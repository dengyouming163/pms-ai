# ADR 0003：回放未命中即失败，不回落真实模型

- 日期：2026-11-21
- 状态：已采纳

## 背景

项目要求"陌生人 clone 后 5 分钟内看到 Agent 改真实房价"，同时要求评测可重复。这两件事都与真实模型冲突：没有 API key 时不能调用模型，有 key 时模型输出又会漂移。需要一个默认离线、可锁定、可解释的运行时。

## 选项

1. **回放未命中时回落真实模型**：体验顺滑，但同一份评测可能在不同机器上走不同路径，基线失去意义。
2. **回放未命中时返回空/默认答案**：不报错，但会把"夹具缺失"伪装成"模型答得不好"，缺陷被掩盖。
3. **回放未命中抛 `FixtureMissing`**：显式失败，强制补夹具。
4. **只支持真实模型**：无 key 用户完全无法运行。

## 决定

采用方案 3：

- `ReplayProvider` 按 `(model, prompt_hash)` 读取 `eval/fixtures/`；
- 未命中直接抛 `FixtureMissing`，禁止回落真实模型或自由生成；
- `LLMProvider=live` 时才走 OpenAI 兼容接口（DeepSeek / 通义 / 火山方舟），并支持 `--record` 录制夹具；
- 评测运行器另有 `ScriptedProvider`，用用例内声明的假输出，连夹具都不依赖。

## 后果

- 无 key 时全流程（四个子图、人审、SSE、评测）可完整运行，且结果确定。
- 夹具缺失是**显式缺陷**：CI 或本地会直接红，而不是随机波动。
- 回放模式只能证明"编排与工具选择正确"，不能证明"模型写得好"；后者需要 `--live --record` 的真实链路与人工评审。
- 评测基线中的 `fixtures_sha256` 用于检测条件漂移：模型、夹具或用例集变化时退出码为 2，拒绝与旧基线比较。
