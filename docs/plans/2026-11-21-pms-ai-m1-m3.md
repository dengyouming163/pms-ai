# 宿智 Agent（pms-ai）实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 把已迁移的 PMS 四模块改造成可一键启动、可回放、可评测、写操作需人审的多智能体协作平台。

**Architecture:** 保留 `pms-server`（Hono + Drizzle）作为唯一业务数据入口，新增内部工具端点；用 `pms-agent`（FastAPI + LangGraph）替换 `pms-ai-crew`，采用 Supervisor + revenue/ops/guest/ota 四个领域子图；`pms-web` 新增 `/agent-console` 协作台，通过 REST + SSE 消费运行状态；评测与演示默认走回放，配置 key 后切真实模型。

**Tech Stack:** TypeScript 5 / Hono 4 / Drizzle ORM / PostgreSQL 16 / Next.js 16 / Python 3.12 / FastAPI / LangGraph / langchain-openai / pytest / Vitest / Docker Compose

**参考规格:** `docs/superpowers/specs/2026-11-21-pms-ai-design.md`

`price-guard.ts` 只做计算，不连库：校验正数、不等于当前价、不低于最低价、变更幅度 ≤ `maxDeltaPct`。返回 `{ ok: boolean; reason?: string; deltaPct: number }`。

```powershell

```

**Step 5: 实现写入端点**

在 `agent-tools.ts` 新增：

```
POST /price-adjust
body: { storeId, roomTypeId, date, expectedCurrentPrice, nextPrice, reason, approvalId }
```

执行顺序（缺一不可）：

1. 校验 `approvalId` 非空。
2. 查询当前日历价格；不存在返回 404。
3. `currentPrice !== expectedCurrentPrice` → 409 `price_conflict`。
4. 调用 `checkPriceAdjustment`，不通过 → 422。
5. 更新 `pms_bui_pricing_calendar.room_types` 中对应房型价格。
6. 返回 `{ ok: true, data: { before, after, deltaPct } }`。

**Step 6: 验证并发冲突**

连续调用同一请求两次：第一次 200，第二次因价格已变返回 409。手工执行两次 `curl.exe` 确认。

`trace.py` 实现 LangGraph 回调：在节点开始/结束、工具开始/结束、模型开始/结束时调用 `append_event`。字段固定：`node, type, payload, started_at, ended_at, tokens_in, tokens_out`。任何异常不得中断主流程（`try/except` 包裹并记 `trace_error`）。

**Step 5: SSE 端点**

`GET /runs/{run_id}/events?after=N`：每 300ms 查一次新事件，`yield f"id: {seq}\ndata: {json}\n\n"`；运行进入终态且无新事件时结束。响应头 `Cache-Control: no-cache`、`X-Accel-Buffering: no`。

**Step 6: 验证**

```powershell

```

预期：事件逐条到达，`seq` 连续递增，终态后连接关闭。
